# Помощь при ошибках запуска

Начните с [инструкций установки в README](../README.md); команды выполняйте из папки проекта в выбранном Python-окружении.
Причины ниже возможные: сверяйте имя отсутствующего модуля, путь к файлу и полный текст ошибки.

## Частые ситуации

| Проблема | Возможная причина | Что сделать |
|---|---|---|
| `ModuleNotFoundError` | Зависимости могли не установиться или установиться для другого интерпретатора. | Выполните `python -m pip install -r requirements.txt` тем же Python, которым запускаете проект. Для отсутствующего модуля проекта также проверьте папку запуска. |
| Отсутствуют обработанные данные или SQLite-база | После клонирования подготовка могла ещё не выполняться; нужные файлы могли быть перемещены. | Выполните подготовку ниже: `download.py`, затем `main.py --run`. Дашборду нужен `data/processed/observations.parquet`, SQL — `data/processed/wells.db`. `--summary` читает сохранённый `outputs/summary.json` и не создаёт эти файлы. |
| Запуск из неправильной папки | Текущий каталог терминала может отличаться от корня проекта. | Перейдите в каталог, содержащий `main.py`, `app.py` и `requirements.txt`, затем повторите нужную команду. |
| Не совпадает SHA-256 исходного CSV (`Checksum mismatch for …`) | Содержимое отличается от закреплённого источника; файл мог быть изменён, повреждён или загружен не полностью. | Перед повторной загрузкой сохраните проблемный CSV отдельно: переместите его из `data/raw/` в другую папку, сохранив содержимое. Затем повторите `python download.py`; не отключайте проверку и не перезаписывайте изменённый файл без сохранения копии. |
| Notebook не видит установленные библиотеки | Выбранный kernel может использовать другое Python-окружение. | Сравните интерпретаторы способом ниже, выберите kernel того же окружения, где установлены зависимости, и перезапустите его после установки. |

## Подготовка отсутствующих файлов

В настроенном окружении из папки проекта выполните по порядку:

```bash
python download.py
python main.py --run
python -m streamlit run app.py
```

Первые две команды подготавливают источники и обработанные файлы; последняя открывает дашборд.
Полный запуск `--run` также пересоздаёт результаты и времена benchmark.
Если нужные файлы уже существуют, повторная подготовка для открытия дашборда не требуется.
При отсутствии базы `main.py --sql` сообщает: `Database missing. Run python main.py --run first.`
При отсутствии обработанного файла дашборд показывает: «Сначала подготовь данные в терминале из папки проекта.»

## Проверка Python-окружения

В терминале посмотрите путь командой `python -c "import sys; print(sys.executable)"`.
В notebook выполните `import sys; print(sys.executable)` и сравните пути.
Для виртуального окружения из Windows-инструкции README заменяйте `python`
на `.\.venv\Scripts\python.exe` в командах терминала, включая установку зависимостей.

`download.py` сверяет SHA-256 с ожидаемым хешем CSV на закреплённой ревизии источника.
Сообщение `Downloaded bytes failed checksum: …` означает, что проверку не прошли уже скачанные байты.
Если повторная загрузка снова не проходит проверку, проверьте соединение и источник; ожидаемый хеш не меняйте.
