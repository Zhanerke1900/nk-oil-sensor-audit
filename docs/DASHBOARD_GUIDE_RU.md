# Краткая демонстрация дашборда

## Подготовка

Установите зависимости по [README](../README.md). Выполняйте команды из папки
проекта в том же Python-окружении; для команд ниже активируйте его:

```bash
python download.py
python main.py --run
python -m streamlit run app.py
```

После `git clone` подготовьте исходные CSV в `data/raw/` и файлы в `data/processed/`:
эти CSV и папка обработанных данных исключены из Git. Первая команда скачивает
и проверяет источники, вторая создаёт обработанные файлы и результаты анализа.
Если необходимые файлы уже созданы, достаточно последней команды — запуска Streamlit.
Откройте адрес из терминала (обычно `http://localhost:8501`); оставьте терминал открытым.

## Сценарий демонстрации

1. В боковой панели выберите «Скважина» → `NK-7`, «Параметр» → `SPM`,
   «Период» → 01.01.2026–30.09.2026, «Выборка» → «Все»,
   «Флаги на графике» → «Все значения».
2. Покажите карточки «Ожидаемые часы», «Наблюдаемые часы»,
   «Отсутствующие часы» и «Полнота данных» над вкладками.
3. Во вкладке «Временной ряд» покажите отметку «Новый режим NK-7»
   от 1 июня 2026 года и изменение SPM после этой даты.
4. Измените «Флаги на графике» на «Без флагов» или «Только с флагами».
   Полнота считается до этой фильтрации и не меняется. Если точек с флагами нет,
   график будет пустым; исключённая фильтром точка не становится отсутствующим часом.
5. Откройте «Пропуски»: покажите отсутствующие строки по дням и почасовую таблицу.
   Здесь учитываются и начальные, и конечные пропуски выбранного периода.
6. Во вкладке «SQL» выберите `04_interior_gaps_lag`: `LAG()` находит внутренние
   пропуски между наблюдениями; граничные пропуски учитываются отдельно.
7. Во вкладке «Сравнение методов» покажите Python, Pandas и SQLite:
   у всех `exact_output_match = True`, 1 677 интервалов и 21 014 отсутствующих часов.

## Объяснение показателей

Для NK-7/SPM за весь период, по [coverage_by_series.csv](../outputs/coverage_by_series.csv):
6 552 ожидаемых часа, 6 420 наблюдаемых, 132 отсутствующих; полнота — 97,99%.
Полнота = наблюдаемые часы / ожидаемые часы × 100% для выбранной серии, периода и выборки.
Общая полнота 91,71% из отчёта рассчитана по всем 43 применимым сериям,
поэтому отличается от полноты одной выбранной серии.

- SQL и сравнение методов показывают сохранённые результаты полного датасета; фильтры панели их не меняют.
- Нулевое показание — существующее наблюдение; отсутствующий час означает отсутствие строки.
- Флаг качества сам по себе не подтверждает поломку оборудования.

## Время выполнения

Benchmark измеряет поиск внутренних пропусков на подготовленных данных после прогрева:
показана медиана трёх запусков, без загрузки CSV, общей сортировки и создания базы.
Время зависит от компьютера и запуска. Источник замеров — [benchmark.csv](../outputs/benchmark.csv),
информация об окружении — [summary.json](../outputs/summary.json).
Отчёт и презентация могут содержать замеры предыдущего запуска: перед защитой
сверьте числа или объясните различие запусков. Для демонстрации сохранённых результатов
повторный ETL не нужен; его запуск перезапишет результаты и времена benchmark.
