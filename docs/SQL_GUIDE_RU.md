# Справочник аналитических SQL-запросов

SQL-анализ описывает состав наблюдений, полноту временных рядов и флаги качества в подготовленной SQLite-базе проекта.

## Двенадцать запросов

| Файл | На какой вопрос отвечает | Как читать результат |
|---|---|---|
| [01_well_inventory.sql](../sql/01_well_inventory.sql) | Какие скважины есть и какие данные они передают? | Одна строка на скважину: число наблюдений и наблюдаемых параметров, первая и последняя даты; `LEFT JOIN` сохраняет и скважины без наблюдений. |
| [02_parameter_statistics.sql](../sql/02_parameter_statistics.sql) | Каковы сводные значения каждого параметра по всем скважинам? | Сравните количество, среднее, минимум и максимум с учётом единиц; `mean_raw_records_per_hour` — среднее `n_obs` исходных записей на часовое наблюдение. |
| [03_monthly_well_trends.sql](../sql/03_monthly_well_trends.sql) | Как меняются показатели скважины и параметра по месяцам? | Строка относится к одной паре и месяцу с наблюдениями; `mean_value` — среднее, `flagged_hours` — число строк с непустым флагом. |

| [10_nk7_regime_comparison.sql](../sql/10_nk7_regime_comparison.sql) | Чем отличаются сохранённые режимы работы NK-7? | Для каждого параметра и `regime` сравните среднее, число наблюдений, нулей, отрицательных значений и строк с флагами. |
| [11_multi_flag_observations.sql](../sql/11_multi_flag_observations.sql) | У каких наблюдений несколько флагов одновременно? | Одна строка — одно наблюдение с `flag_count > 1`; `individual_flags` перечисляет его отдельные флаги через `;`. |

## Важные различия

Серия — применимая пара «скважина–параметр» из `well_parameters`.
Запрос 07 начинает с этой таблицы, поэтому включает применимые серии даже без наблюдений.
Ожидание 6 552 часа относится к полному периоду 01.01.2026–30.09.2026.

В запросе 04 `LAG()` видит только соседние существующие строки внутри серии.
Для пропусков до первой и после последней строки нужна отдельная проверка;
её сохранённые результаты находятся в [gaps_boundary.csv](../outputs/gaps_boundary.csv).

В запросе 08 рекурсивный календарь и `LEFT JOIN` сохраняют дни без единой записи.
Это покрытие всех применимых серий за день, а не одной выбранной скважины.
Нулевое показание остаётся наблюдением и само по себе не является пропущенным часом.

Число отдельных флагов в запросах 05 и 11 отличается от числа флаговых наблюдений:
одно наблюдение может иметь несколько флагов. Флаг сам по себе не доказывает поломку.

## Сохранённые результаты и повторный запуск

CSV-результаты находятся в [outputs/sql/](../outputs/sql/); имя совпадает с именем запроса.
Файл `sql/schema.sql` описывает структуру базы и не входит в эти 12 запросов.

Из папки проекта в настроенном Python-окружении выполните:

```bash
python main.py --sql
```

Команда повторно выполняет запросы по существующей `data/processed/wells.db`
и заново сохраняет результаты; она не загружает источники и не запускает полный ETL.
Если база ещё не создана, сначала подготовьте проект по [README](../README.md):
`python download.py`, затем `python main.py --run`.
